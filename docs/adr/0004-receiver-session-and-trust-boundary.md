# ADR-0004: 検証済みメタデータで受信セッションを確立し、保存先は受信側が所有する

## 決定

受信側は、通信形式として有効で、ローカルの最大チャンク数以下である**最初のメタデータ**を採用した時点で、その受信処理の転送セッションを確立します。

メタデータ採用前のデータは使用しません。セッション確立後は、メタデータのセッションID、チャンクサイズ、チャンク数、ファイルサイズ、SHA-256を固定し、その条件に適合するデータだけを処理します。後から別セッションの有効なメタデータが届いても切り替えません。

ネットワーク入力は内部状態を変更する前に、データグラム長、共通ヘッダー、セッションID、各項目、UTF-8、シーケンス範囲、期待データ長を検証します。不正データは受信状態や `.part` を進めません。

メタデータに含まれる送信元ファイル名は利用者向け表示だけに使います。出力パスは受信側CLIで明示し、送信側に保存先を決めさせません。表示時は制御文字をエスケープします。

ランダムセッションIDは採用済み転送への別転送パケット混入を防ぐ識別子です。送信者認証、認可、暗号化、MAC、電子署名ではありません。また、期待するセッションIDを受信開始前に指定する機能は設けません。

## 理由

同じUDPポートには、前回転送の遅延パケット、別送信プロセス、短いパケット、不正メタデータなどが到着し得ます。検証前に状態へ反映すると、別転送データの混入、誤ったファイル位置、受信状態の過大化につながります。

128 bitランダムセッションIDを全パケットに含めることで、応答通信やハンドシェイクを追加せず、片方向通信のまま**採用後の転送単位**を分離できます。一方、受信側は最初に受理可能なメタデータを採用するため、セッションIDだけでは「誰の転送を受けるか」を決定できません。この信頼境界は文書で明示し、送信元の制限はOS、ファイアウォール、ネットワーク構成へ委ねます。

送信側由来のファイル名を保存パスに使用すると、ネットワーク入力が受信ホストの保存先を支配します。保存先をローカル利用者の指定に限定し、転送メタデータとファイルシステム方針を分離します。

## 結果

- 1回の受信処理は1転送セッションだけを扱います。
- 最初に採用したメタデータがその受信処理中は固定されます。
- 別セッションのデータや後着メタデータは現在の転送へ使用しません。
- 上限超過メタデータでは最終出力も `.part` も開きません。
- 送信元ファイル名から保存先を自動決定しません。
- セッションIDやSHA-256が一致しても送信者の真正性は保証しません。
- 信頼できない送信元が待受ポートへ到達できる環境では、ネットワーク側の到達制御が必要です。
