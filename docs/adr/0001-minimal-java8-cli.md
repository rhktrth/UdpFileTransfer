# ADR-0001: Java 8 の小規模 CLI として実装を閉じる

## 決定

UdpFileTransfer は単一 Maven モジュールの Java 8 CLI とし、製品実行時の依存は JDK 標準ライブラリだけとします。

製品コードの責務は CLI とプロセスのライフサイクル、送信、受信、通信形式、ファイルハッシュに限定します。単独で再利用しない小さな解析処理やデータモデルは、その責務を所有するクラスの内側に置きます。将来拡張だけを理由にフレームワーク、DIコンテナ、プラグイン機構、共通層を追加しません。

Maven をビルドの正本とし、IDE 固有構成をアーキテクチャの前提にしません。

## 理由

このツールは、片方向通信という特殊な環境で確実に持ち込んで実行でき、少人数でもプロトコルとファイル再構成の全体を追跡できることが重要です。

外部実行時依存や汎用フレームワークを増やすと、配布、依存更新、障害解析、テストの面積が用途に対して大きくなります。JDK の NIO、ファイル、UDP API へ設計を直接対応させることで、通信パケット、ファイル位置、欠損状態の関係をコードから追いやすく保てます。

Java 8 は現在の実行要件であり、その範囲で利用できる言語機能とAPIは、処理を短く明確にする場合に使用します。

## 結果

- 実行時依存の追加は例外扱いとし、JDKだけでは満たせない具体的要件がある場合に再検討します。
- 責務が増えていないのにクラスや抽象化を増やしません。
- 小さな内部モデルを再利用性だけを理由に独立コンポーネント化しません。
- 過去バージョンとの互換層は標準では持ちません。
- 大規模フレームワークを前提とする機能要求が生じた場合は、この判断を見直します。
