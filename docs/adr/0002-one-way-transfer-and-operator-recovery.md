# ADR-0002: 転送ネットワークを片方向のまま保ち、信頼性回復を利用者へ委ねる

## 決定

UdpFileTransfer のファイル転送プロトコルは、送信側から受信側への片方向通信だけで成立させます。

受信側から送信側へ ACK / NACK、欠損通知、完了通知、フロー制御を返しません。UDP パケットの欠落は受信側が未受信シーケンスとして観測し、その番号を利用者が電話、チャット、別ネットワークなどプロトコル外の経路で送信側へ伝え、必要なデータチャンクを明示的に再送します。

全送信時はメタデータを2回送った後に全データチャンクを1回ずつ送りますが、これは単純な損失低減であり到達保証ではありません。

## 理由

このツールの成立条件は、戻り経路が存在しない、またはポリシー上使用できない環境でもファイル転送を実行できることです。

ACK/NACK や自動再送をプロトコルに導入すると受信側から送信側への通信経路が必要になり、この最重要条件を失います。また、送達状態、タイムアウト、再送回数、フロー制御などの分散状態を追加すると、プロトコルと運用の複雑さも増えます。

欠損をシーケンス番号として可視化し、復旧判断を利用者へ委ねることで、データ経路の一方向性を守ったまま必要なチャンクだけを再送できます。

## 結果

- 送信側単独では転送完了を知りません。
- パケット欠落が発生した場合、完全な転送には利用者と帯域外の連絡手段が必要です。
- 自動再送、タイムアウト交渉、輻輳制御は行いません。
- 受信側が未受信シーケンスを正確に保持・表示できることが信頼性回復の重要な前提になります。
- 双方向ネットワークを前提に自律的な信頼性保証が必要になった場合は、この判断自体を見直します。
